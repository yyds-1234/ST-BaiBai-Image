# 柏宝绘 · DSH 画面占位（世界书）

指导主模型在每轮回复末尾输出画面占位，交给柏宝绘 → DSH 写手 → 出图。

## 文件

| 文件 | 用途 |
|---|---|
| `01-柏宝绘-DSH画面占位.json` | **可直接导入的独立世界书**（酒馆：世界书页面 → 导入） |
| `01-柏宝绘-DSH画面占位.json` 的 uid 1 | 与 `src/autoTag/dshPlaceholder.ts` 的 `DSH_WORLDBOOK_ENTRY` **逐字相同**（面板「复制世界书条目」给的就是这条） |

设计口径：

- **只留 1 条常驻**。主协议是唯一的必读项，其余三条都是「聊到了才用得上」，用关键词触发，
  不占每轮预算。递归双禁（`excludeRecursion` / `preventRecursion`），条目之间不会互相拉起。
- **绿灯条目注入用户 D0**（`position=4 / depth=0 / role=1`）。关键词条目只在命中的那轮出现，
  插在提示词中段会让其后的历史整体位移、打断上游前缀缓存；注入 D0 则前缀逐字节稳定。
- **条目正文没有任何 markdown**。它是原样拼进提示词的：`##` 与 `**` 会被模型当成「照这个格式接着写」，
  于是在 `<dsh>` 里也带上装饰。

## 格式约定（与插件解析器同源）

```
<bbi_image><dsh>中文散文，一段不换行</dsh><size>portrait</size></bbi_image>
```

- `<size>` 只取 `portrait` / `landscape`，小写；缺省按 portrait。
- 一次回复最多一条，**插在它描述的那一段正文之后**，不是全文末尾。
  卡片落在占位所在的行内位置：攒到最后的写法会让图挂在全文尾部，图和情节对不上。
- 占位在显示与提示词两条路径上都被替换掉，永不进 DOM、永不进提示词。
- `<dsh>` 里出现任何 `<bbi_image>` / `<tag>` / `<nl>` / `<size>` / `<dsh>` 字面量都会被判非法
  （查找正则非贪婪，漏一个就从那里截断，正文会漏进 DOM）。

## 导入后

1. 世界书页面导入 JSON，把这本书挂到聊天上（或设为全局）。
2. 柏宝绘侧栏 → DSH 桥接 → 测试连接，确认 `llm.available` 与协议版本 2。
3. 随便聊几轮，回复末尾应出现 `<bbi_image><dsh>…</dsh><size>…</size></bbi_image>`，
   卡片会显示「DSH 写手 · N 字画面描述」。
4. 点卡片出图；出图失败或写法不对，去 DSH 配置台 `/story-image-admin` 的「请求历史」看这一次请求的
   system / 占位 / 出稿 / 耗时。
